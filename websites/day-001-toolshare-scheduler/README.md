# ToolShare Scheduler\n\n## Overview\nA static, mobile‑responsive web app that lets a neighbourhood community manage a shared tool shed. Users can add tools, reserve them for a date range, mark them as returned, and export/import the entire inventory as JSON. All data is stored locally in the browser (localStorage), so no backend or login is required.\n\n## How to Use\n1. Open `index.html` in a browser (GitHub Pages works out of the box).\n2. **Add a tool** – fill *Name* and *Quantity* and click *Save Tool*.\n3. The tool appears in the list with an *Available* status.\n4. **Reserve** – click *Reserve* and enter an end date (`YYYY‑MM‑DD`). The status changes to *Reserved until …*.\n5. **Return** – once the tool is back, click *Return* to free it.\n6. **Export** – click *Export JSON* to download the current data.\n7. **Import** – click *Import JSON* and select a previously exported file to restore data (useful for the caretaker).\n\n## Technical Details\n- **HTML5** semantic structure, accessible labels, and keyboard‑friendly buttons.\n- **CSS** uses a simple responsive layout; works on phones, tablets and desktops.\n- **JavaScript** vanilla ES6, no frameworks. Data persistence via `localStorage`.\n- No external libraries, trackers, or APIs – fully self‑contained and safe to host on GitHub Pages.\n\n## Business Hypothesis\n- **Target customers**: housing societies, co‑ops, and NGOs with shared resources.\n- **Problem**: manual logs cause double‑booking and lost tools.\n- **Solution**: free web UI that eliminates paper and sync issues.\n- **Monetization**: freemium – core features stay free; premium add‑ons (cloud sync, email reminders) could be sold for a small annual fee.\n- **Operating costs**: ₹0 while hosted on the free tier of GitHub Pages.\n\n## Testing Checklist\n- Add a new tool and verify it appears.\n- Reserve a tool, close/reopen the browser, ensure reservation persists.\n- Return a tool and see status update.\n- Export JSON, clear localStorage via browser dev tools, import the file and confirm data restores.\n\n## Limitations\n- Data is stored per browser; different users on different devices will not share the same state unless they manually import/export.\n- No authentication or server‑side validation – suitable only for trusted small groups.\n- Date validation is minimal (prompt).\n\n## Future Improvements\n- Optional Google Drive sync for multi‑device backup.\n- Serverless email reminders for reservations.\n- QR code labels for each tool to scan with phones.\n\n---\n*This project is a prototype intended for educational and community use.*
