# StudyBuddy Scheduler\n\n## Overview\nStudyBuddy Scheduler is a static, mobile‑responsive web app that lets students post short study‑session offers or requests and claim sessions instantly. All data is stored locally in the browser, so no backend or login is required.\n\n## Features\n- Create a study session (offer or request) with subject, date, time, location, and optional notes.\n- Filter public listings by subject, date, or location.\n- Claim a session with one click; claimed sessions appear in a personal list.\n- Data persists across page reloads using `localStorage`.\n- Fully responsive layout works on phones, tablets, and desktops.\n\n## Usage\n1. Open `index.html` in a browser (GitHub Pages URL works as well).\n2. Click **Add Session** to create a new listing.\n3. Use the filter controls to narrow down sessions.\n4. Click **Claim** on a session you want to join; it moves to **My Sessions**.\n\n## Testing (manual)\n- **Add Session**: Fill the form completely and save. The new entry should appear in the list.\n- **Filter**: Select a subject or enter a location; only matching entries remain visible.\n- **Claim**: Press *Claim* on a listing; it disappears from the public list and shows under *My Sessions*.\n\n## Business Hypothesis\n- **Target customers**: Students in schools, colleges, and study groups.\n- **Problem**: Difficulty finding peers for ad‑hoc study sessions.\n- **Solution Differentiator**: No registration, no ads, purely peer‑to‑peer matching, hosted for free.\n- **Monetization**: Freemium model – basic matching stays free; premium filters (e.g., by GPA, study style) offered for a small monthly fee after reaching a critical user base.\n- **Operating costs**: Zero while hosted on GitHub Pages.\n\n## Limitations\n- Data is stored only in the user’s browser; sessions are not shared across devices.\n- No authentication, so users cannot protect their listings.\n- Advanced matching (skill level, availability sync) requires a backend, which is out of scope for the prototype.\n\n## Future Improvements\n- Optional cloud sync using a serverless function or Firebase.\n- User profiles with email notifications.\n- Rating system for partners and recurring session templates.\n\n---\n\n*This prototype is intended for validation and early user feedback. All code is open‑source and can be forked for further development.*
